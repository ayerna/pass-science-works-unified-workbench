1. Executive Summary & Architecture (Task A)

The Unified Engineering Workbench is delivered as a decoupled dual-layer architecture: 1. C++17 Core Engine (workbench.exe): High-performance CLI binary compiled with zero external dependencies (C++ standard library only). Implements strict STL/CSV parsing, 1D steady-state thermal FEA, multicore parallel batch solving with a bounded thread pool, backpropagation with finite-difference gradient verification, and mock embedded adapters. 2. Interactive Presentation Layer (frontend/index.html): Single-page web application offering Geometry, Thermal, Performance, and Hardware views. Visualizes ASCII STL CAD meshes, displays colored 3D ANSYS temperature point clouds with inspection, plots FEA convergence curves, and drives interactive embedded hardware simulation. 3. One-Click Delivery (Launch.exe): Native Windows GUI-subsystem binary (541 KB, statically linked with MinGW-w64 runtime, importing only system DLLs KERNEL32, msvcrt, SHELL32, USER32). Double-clicking Launch.exe spawns workbench.exe all without popping up a console window, regenerates results/*.csv, and automatically opens frontend/index.html in the user's default browser via ShellExecuteA. No installation, administrator privileges, first-run build, or internet connection is required. - Launch-to-Ready Time: Unconfirmed on a clean Windows 11 machine; no timing is claimed here. 4. Editor One-Action Run: Configured via .vscode/launch.json running scripts/serve.py (Python 3 standard library only), serving the application on http://localhost:8000 (verified HTTP 200). Full source builds are supported across Windows and Linux via CMake 3.28+.

3. Thermal FEA Verification (Task C)

Governing Physics & Exact Formulation

Steady-state 1D heat conduction along a uniform rod with internal heat generation: $$-k A \frac{d^2 T}{dx^2} = q A \quad \implies \quad \frac{d^2 T}{dx^2} = -\frac{q}{k}$$ - Parameters: Length $L = 1.0\text{ m}$, Area $A = 10^{-4}\text{ m}^2$, Conductivity $k = 10.0\text{ W/(m}\cdot\text{K)}$, Heat Source $q = 10,000\text{ W/m}^3$. - Boundary Conditions: Dirichlet temperature constraints $T(0) = 100^\circ\text{C}$, $T(L) = 20^\circ\text{C}$. - Analytical Solution: Integrating twice with boundary conditions yields: $$T(x) = 100 - 80x + 500x(1 - x)$$ Peak temperature occurs at $x = 0.42\text{ m}$ with $T_{\max} = 108.2^\circ\text{C}$.

Finite Element Formulation

Linear two-node 1D elements with element stiffness matrix $K^{(e)} = \frac{kA}{h} \begin{bmatrix} 1 & -1 \ -1 & 1 \end{bmatrix}$ and uniform thermal load vector $F^{(e)} = \frac{qAh}{2} \begin{bmatrix} 1 \ 1 \end{bmatrix}$. Dirichlet boundary conditions are enforced by moving known columns to the right-hand side force vector, preserving symmetry and avoiding matrix distortion.

Moving known Dirichlet terms $K_{i,0} T_0$ and $K_{i,N} T_N$ directly to the RHS prior to solving fixed this issue cleanly.

4. Multicore Concurrency & Benchmarking (Task D)

Workload Specification

  • 200 independent 1D thermal FEA cases ($N=40$ elements per case), generated with pseudo-random positive parameters ($k \in [5, 20]\text{ W/(m}\cdot\text{K)}$, $q \in [5000, 20000]\text{ W/m}^3$) seeded deterministically (seed = 42).
  • Bounded worker thread pool (src/parallel_batch.hpp) with task queue; results collected into pre-allocated slots indexed by input order to guarantee deterministic ordering.
  • Timing protocol: warm-up run excluded; 5 timed repetitions; median wall-clock time reported. Hardware: AMD Ryzen 5 5600H @ 3.3 GHz (6 cores / 12 logical processors), 15.3 GB RAM, Windows 11 Home x64, MinGW-w64 GCC 13 (-O2).

  • Numerical Precision: Maximum difference between serial and parallel solutions across all 200 cases is exactly 0.0°C, well within the required $10^{-8\circ}\text{C}$ threshold.
  • Performance Analysis & Limitations: Because 200 cases of 40-element linear solves take less than 0.5 ms total, thread synchronization (mutex locking, condition variable notification, and OS thread scheduling) incurs overhead comparable to the entire computation. Consequently, scaling at 2 workers dips below 1.0 on this modern high-clock CPU before recovering slightly at 4 workers. This is mathematically expected for tiny workloads and is reported transparently rather than artificially inflated.

5. Embedded Host Workbench Architecture (Task E)

Topology & Hardware Interconnect

The workbench simulates a host engineering station controlling three target devices via USB: 1. MCU Board (STM32 Nucleo-64 Style): 3.3 V domain; host communication over virtual USB-CDC UART; onboard ST-LINK owns SWD/JTAG debug lines. 2. FPGA Board (Artix-7 Style): Dual-rail power (1.8 V core, 3.3 V I/O bank); host communication via USB-JTAG; dedicated JTAG chain connects FPGA configuration logic. 3. Dedicated JTAG Adapter (Bus Blaster / J-Link Style): Host USB interface converting packets to physical TAP state-machine signals (TCK, TMS, TDI, TDO, nTRST). Features active bidirectional level shifters supporting target voltages from 1.2 V to 5.0 V.

JTAG Adapter USB 2.0 (High-Speed) 1.2 V – 5.0 V VREF TCK, TMS, TDI, TDO, nTRST TXB0108 / SN74AVC level-translator
  • Why JTAG is a Debug Interface, Not a Generic Compute Board: JTAG (IEEE 1149.1) is a serial boundary-scan test interface driving an internal 16-state TAP finite-state machine. It shifts bits through instruction and data shift registers (BSR, IDCODE, BYPASS) to inspect pins or control debug hardware inside an MCU/FPGA. It possesses no CPU instruction decoder, ALU, application memory, or operating runtime, and cannot execute user computational workloads.
  • C++ Mock Verification & Fault Recovery: src/main.cpp implements discovery, capability queries, and telemetry for all 3 devices (MCU Temp = 36.5°C, FPGA Done = 1). It implements a simulated JTAG hardware probe timeout: on the initial attempt, a timeout error is triggered; the controller automatically recovers via a bus reset and retry without crashing or corrupting state.
  • Safe Hardware Integration Rules: (1) Connect common ground (GND) before signal lines; (2) Sense and verify $V_{\text{target}}$ prior to enabling JTAG buffers; (3) Power targets independently; (4) De-energize target rails prior to rewiring.

6. Backpropagation & Gradient Verification (Task F)

Network Topology & Forward Pass

A compact single-input single-output regression network with one hidden unit: $$\text{Hidden: } z = w x + b, \quad h = \tanh(z) \qquad \text{Output: } \hat{y} = v h + c \qquad \text{Loss: } J = \frac{1}{2}(\hat{y} - y)^2$$ - Initial Values: Input $x = 1$, Target $y = 2.0$; Weights $w = 0.5$, $v = 1.0$; Biases $b = 0$, $c = 0.0$. - Forward Numerical Evaluation: $$z = 0.5(1) + 0 = 0.500000$$ $$h = \tanh(0.5) \approx 0.462117157$$ $$\hat{y} = 1.0(0.462117157) + 0.0 = 0.462117157$$ $$J = \frac{1}{2}(0.462117157 - 2.0)^2 = \frac{1}{2}(-1.537882843)^2 \approx 1.182541819$$

Analytical Gradients via Chain Rule

Let residual $\delta_{\text{out}} = \frac{\partial J}{\partial \hat{y}} = (\hat{y} - y) = -1.537882843$. 1. $\frac{\partial J}{\partial c} = \delta_{\text{out}} \cdot 1 = \mathbf{-1.537882843}$ 2. $\frac{\partial J}{\partial v} = \delta_{\text{out}} \cdot h = (-1.537882843)(0.462117157) = \mathbf{-0.710682052}$ 3. $\frac{\partial J}{\partial z} = \delta_{\text{out}} \cdot v \cdot (1 - h^2) = (-1.537882843)(1.0)(1 - 0.462117157^2) = \mathbf{-1.209463660}$ 4. $\frac{\partial J}{\partial w} = \frac{\partial J}{\partial z} \cdot x = (-1.209463660)(1) = \mathbf{-1.209463660}$ 5. $\frac{\partial J}{\partial b} = \frac{\partial J}{\partial z} \cdot 1 = \mathbf{-1.209463660}$

Finite-Difference Verification: Central differences $\frac{J(\theta + \epsilon) - J(\theta - \epsilon)}{2\epsilon}$ with step $\epsilon = 10^{-6}$ evaluated in src/backprop.hpp match the analytical values with errors $\sim 10^{-10}$, exceeding the required $10^{-5}$ tolerance.

Parameter Update & 100-Step Optimization

Figure 3: Monotonic loss descent over 100 steps (log10 scale)

Using learning rate $\eta = 0.1$, parameters update simultaneously: $\theta \leftarrow \theta - \eta \frac{\partial J}{\partial \theta}$. All gradients are negative because prediction $\hat{y} < y$; thus gradient descent increases all 4 parameters. - Updated values: $w \approx 0.620946$, $b \approx 0.120946$, $v \approx 1.071068$, $c \approx 0.153788$. - New loss drops from 1.182542 to 0.685774 in step 1. - After 100 iterations, loss reaches $1.70 \times 10^{-20}$. Fitting 4 degrees of freedom to a single observation demonstrates exact numerical optimization, not generalized machine learning. - (Handwritten Appendix: Full forward pass, chain-rule equations, and update step attached by candidate as 2-page appendix).
